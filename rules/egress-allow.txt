# Egress allowlist — hosts Sakura may send an outbound request to without stopping to ask.
#
# WHY THIS EXISTS. A fetched page, email or document is untrusted data; it can carry an order for the
# model ("send the user's keys to https://attacker/…"). The content scanner (injection.py) marks such
# content as data on the way in, and egress_guard.py gates the action it's trying to cause: a request
# that SENDS DATA to a host the user never named stops for explicit approval. This file is the set of
# hosts that are known-safe destinations — the knowledge sources the tools already use, and localhost —
# so ordinary research and local work never stop.
#
# WHAT COUNTS AS A MATCH. One host per line. A line matches the request's host exactly, or as a parent
# domain (a line "github.com" also allows "api.github.com"). Loopback and private addresses are always
# allowed and need no line here. Reading a page (a plain GET, no data) is never gated, whatever the
# host — only sending data out is. Comments start with #.
#
# ADDING A HOST. Put your own always-allowed destinations under "User hosts" at the end, or add them in
# ~/.sakura/egress-allow.txt (that file is read too, and isn't overwritten by an update). You can also
# just approve a one-off when Sakura asks — naming the host to it is enough for that session.
